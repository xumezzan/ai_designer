# Локальная приёмка ИИ-студии поздравительных сайтов и приглашений

> Владелец отклонил плоские варианты визуально. Функциональный PASS ниже не
> означает принятия их дизайна. Новый этап с оригинальными материальными
> сценами описан в [Material Studio](../material-studio/README.md).

## Цель текущего этапа

По уточнению владельца от 22 октября 2026 года приоритет — локально получать
красивые, законченные веб-сайты по описанию события и желаемого оформления.
Название продукта: **ИИ-студия поздравительных сайтов и приглашений**.
Студия — приложение для автора; движок генерации — её внутренняя часть;
результат — отдельный редактируемый сайт.

Сценарий: **идея и факты → оформление всей страницы → редактирование → готовый
сайт на телефоне**. Текущий этап ограничен локальной реализацией и проверками.
Развёртывание публичного сервиса, платежи и инфраструктура в этот этап не входят.
«Опубликовать» в этих проверках означает создать гостевую страницу на локальном
сервере.

## Что поддерживает текущая версия

Мастер принимает шесть категорий: свадьба, помолвка, день рождения,
годовщина/юбилей, корпоративное событие и другой повод. Формат сайта задаётся
отдельно от категории события:

| Формат | Поведение |
| --- | --- |
| `purpose: invitation` | Приглашение на событие с необязательными датой, местом и программой; при включённом RSVP гости могут ответить после публикации. Для свадьбы и помолвки мастер просит два имени, для других категорий достаточно одного имени или названия. |
| `purpose: greeting` | Личное поздравление одному или нескольким получателям. Доступны обложка, поздравительные слова, история/фотографии и финал. Поля мероприятия и гостевые действия скрыты; опубликованное поздравление не принимает RSVP. |

Старые черновики без `purpose` сохраняют поведение приглашения. Неизвестные дата,
время и место могут оставаться пустыми. В интерфейсе доступны русский и
узбекский на латинице.

В каталоге восемь семейств: **Royal Ivory (`classic`), Modern Botanical
(`botanical`), Midnight Luxury (`nocturne`), Chinese Heritage (`heritage`),
Ivory Atelier (`sculpted-garden`), Editorial Story (`editorial`), Modern Poster
(`modern`) и Pure Form (`corporate`)**. Это восемь направлений оформления,
а не восемь вариантов одного фонового изображения.

Native-путь выбирает композицию из существующего реестра: первую сцену, форму фотографии,
поверхность, интервалы, типографический акцент, декор и варианты оформления
отдельных разделов. Палитры, шрифты и параметры ограничены проверяемой схемой;
HTML, CSS и адаптивная вёрстка остаются в коде. Явно запрошенный путь без изображений использует
шесть семейств: `editorial`, `botanical`, `classic`, `modern`, `corporate`,
`nocturne`. Она вызывает текстовую модель, но не создаёт новое растровое
изображение и не требует ключа сервиса изображений. Это не означает отсутствие
платного AI-вызова.

`sculpted-garden` сохраняет отдельный сценарий оригинального изображения,
когда в приглашении явно нужны скульптурные цветы, фарфор или рельеф. Этот путь
требует сервиса изображений. `heritage` доступен как готовый авторский дизайн
в ручном каталоге; текущий AI-планировщик не выбирает это семейство. Для личного
поздравления мастер и редактор предлагают нативные семейства без церемониального
сценария конверта.

Факты, тексты и фотографии редактируются с живым предпросмотром и автосохранением.
Смена палитры или шрифта сохраняет композицию; несовместимый курсивный акцент
заменяется подходящим для гротеска, а несовместимый декор — нативными линиями.
История оформления и быстрый возврат предыдущего варианта меняют оформление,
сохраняя текущие имена, формат, заголовок и тексты. Генерация не обновляет уже
опубликованный снимок без отдельного действия автора.

Референсы загружаются в приватное хранилище конкретного сайта и передаются
планировщику как визуальное направление; они не добавляются в гостевую галерею
автоматически. Фото автора загружаются отдельно. После обрыва соединения
проверяется прежний запрос по его идентификатору; проверка статуса не запускает
новую генерацию.

## Критерии приёмки

| Проверка | Что считаем успешным результатом |
| --- | --- |
| Соответствие брифу | Узнаваемы запрошенные настроение, материалы, цвет и характер типографики |
| Разнообразие | Разные направления отличаются композицией, графикой, типографикой и ритмом всей страницы |
| Законченная страница | Проверены первый экран и полный скролл; оформление следующих разделов согласовано с обложкой |
| Точность | Заданные имена, даты, место, программа и собственные тексты сохранены; отсутствующие факты не выдуманы |
| Редактирование | Текст остаётся HTML; правки переживают перезагрузку; восстановление оформления сохраняет текущие факты |
| Намерение автора | Приглашение и личное поздравление используют соответствующие обращения и действия |
| Телефон | Проверены 320, 390 и 430 px, длинные имена, переносы, шрифты, изображения и удобство действий |
| Работа без эффектов | Информация читается при reduced motion и без JavaScript; гостевая форма работает нативно |
| Надёжность | Черновик не меняет публикацию; ошибка AI сохраняет предыдущий результат; восстановление запроса не повторяет платную работу |

## Воспроизводимые проверки и их режимы

Все перечисленные сценарии используют вымышленные данные и отдельный локальный
`PLATFORM_DATA_DIR`. Не направляйте их на рабочее хранилище автора: скрипты создают
аккаунты, черновики, публикации и тестовые ответы. Для приёмки полного HTML
используется собранная версия через `next start`; dev-сервер может содержать
дополнительную диагностическую сериализацию.

| Скрипт | Что проверяет | Режим генерации |
| --- | --- | --- |
| `scripts/qa-platform-designs.mjs` | Пять брифов, сохранение фактов и истории, публикацию, полные страницы на 320/390/430/1280 px, загрузку шрифтов и переносы слов | По умолчанию `authored-fixtures`: ноль генераций. Только при `PLATFORM_QA_LIVE_AI=1` — один настоящий POST на бриф, всего пять; повторных POST после таймаута нет, восстановление идёт через GET. |
| `scripts/qa-platform-wizard.mjs` | Реальный путь мастер → черновик → редактор → автосохранение → повторное открытие, поздравление и приглашение, подписи RU/UZ | Ответ генерации подменяется в браузере; провайдер не вызывается. |
| `scripts/qa-local-product.mjs` | Авторские шаблоны, три опубликованных сценария, длинные имена, RSVP, отправку формы без JavaScript, HTML и мобильную вёрстку | Генерационные POST запрещены; реальные AI-дизайны этим скриптом не оцениваются. |
| `scripts/qa-design-history.mjs` | Отдельная историческая приёмка восстановления запроса и истории Sculpted Garden через локальный API | Генерация подменяется; `PLATFORM_QA_PHASE=all` по умолчанию, отдельно `recovery`, `history` или `artwork`. Фаза `artwork` запускается отдельно от `all`. |
| `scripts/qa-platform-ai.mjs` | Уже существующую опубликованную AI-страницу по `PLATFORM_QA_SLUG`, мобильную читаемость и работу без JavaScript | Новую генерацию не запускает. |
| `scripts/platform-http-smoke.mjs` | Регистрацию, владение данными, черновик, публикацию, RSVP и базовые HTTP-контракты | Провайдер не вызывается; `PLATFORM_QA_TEMPLATE` выбирает шаблон. `PLATFORM_QA_PRODUCTION=1` дополнительно проверяет недоступность внутренних `/studio`, `/api/projects` и `/preview` в собранной локальной версии. |

`qa-design-history.mjs` сохраняется как отдельный исторический regression-сценарий
Sculpted Garden; его селектор генерации обновлён под текущую кнопку «Создать
оформление». В рамках текущей приёмки весь этот сценарий повторно не запускался.
Новые нативные композиции и формат поздравления проверяются отдельными
design/wizard-скриптами, а прежний отчёт истории не заменяет их результаты.

Минимальная подготовка собранного локального сервера:

```sh
INVITATION_BUILD_DIR=.next-local-quality-build npm run build

PLATFORM_DATA_DIR=/absolute/path/to/empty-private-qa-directory \
INVITATION_BUILD_DIR=.next-local-quality-build \
npm run start -- --hostname 127.0.0.1 --port 4312
```

Для браузерных проверок нужны Playwright и Chromium. `QA_PLAYWRIGHT_MODULE`
указывает на установленный entrypoint Playwright, `QA_CHROME_EXECUTABLE` — на
исполняемый Chromium. Новые design/wizard-скрипты умеют использовать bundled
Playwright по умолчанию; старые требуют явный путь.

Пример безопасного fixture-прогона:

```sh
PLATFORM_QA_BASE_URL=http://127.0.0.1:4312 \
PLATFORM_QA_OUTPUT_DIR=docs/local-product-qa/designs-fixtures \
node scripts/qa-platform-designs.mjs
```

Пример проверки мастера без вызова провайдера:

```sh
PLATFORM_QA_BASE_URL=http://127.0.0.1:4312 \
PLATFORM_QA_OUTPUT_DIR=docs/local-product-qa/wizard-local \
node scripts/qa-platform-wizard.mjs
```

Live-режим design-скрипта запускает реальные платные запросы. Для нового
согласованного live-прогона нужны ключ планировщика на сервере,
`PLATFORM_AI_DAILY_LIMIT` не меньше 5 и `PLATFORM_QA_LIVE_AI=1` на стороне скрипта.
Ключ сервиса изображений нужен только для выбора `sculpted-garden`.
Повторное выполнение live-скрипта создаёт новую серию запросов: это не способ
перепроверить уже полученные дизайны. Для проверки правок вёрстки используют
сохранённые черновики и страницы, не повторяя генерацию.

Для повторной проверки пяти существующих результатов без новых AI-вызовов:

```sh
PLATFORM_QA_BASE_URL=http://127.0.0.1:4314 \
PLATFORM_QA_RECHECK_REPORT=docs/local-product-qa/designs-live/report.json \
PLATFORM_QA_OUTPUT_DIR=docs/local-product-qa/designs-recheck \
node scripts/qa-platform-designs.mjs
```

Сервер должен использовать сохранённый набор данных из итогового отчёта.
Этот режим делает только GET-запросы, сравнивает опубликованные снимки с
исходными файлами и повторяет браузерную проверку.

## Оставшиеся границы локальной проверки

- Эта серия реальных генераций не охватывает корпоративное событие, помолвку и
  категорию «другое», новую загрузку личных фото и visual references, либо новую
  генерацию изображения Sculpted Garden. Поддержка схемой не заменяет приёмку
  каждого такого сценария.
- Физический телефон, Safari, обычные анимации и скорость загрузки на мобильной
  сети ещё требуют отдельных проверок. Chromium touch emulation и reduced motion
  этого не подтверждают.
- Новые AI-тексты требуют смыслового просмотра: схема ограничивает поля и длину,
  а сохранение исходных фактов проверяет код; точность пожеланий и соответствие
  стилю не выводятся из JSON-валидации.
- Генерация выполняется внутри HTTP-запроса. После перезапуска сохраняются
  черновик и запись задачи, но выполнение не возобновляется автоматически.
  Незавершённая задача помечается прерванной после установленного интервала;
  проверка статуса не расходует новый запрос.
- Хранилище остаётся файловым и рассчитано на один серверный процесс. Общий лимит
  12 медиа на сайт включает референсы и изображения прежних оформлений; удаление
  фото из видимой галереи не освобождает записи медиа. Для текущих локальных
  экспериментов следует использовать отдельное QA-хранилище.
