# Авторский каталог вместо свободной генерации дизайна

Концепция из файла «Сервис онлайн-приглашений: как сделать дизайн как от студии»
внедрена в рабочий путь создания приглашений. Модель выбирает готовую композицию
и разрешённые настройки. Шрифтовые размеры, отступы, форма, декор, материалы,
семантический порядок и движение принадлежат коду.

## Каталог

`/templates` показывает шесть авторских примеров. Их данные вымышленные и никогда
не подставляются в проект клиента.

| Шаблон | Характер | Основные события |
| --- | --- | --- |
| Editorial | Журнальная шапка, выразительные имена, центральное фото, разные роли разделов | Свадьба |
| Ботаника | Арочная композиция, оригинальная гравюра, спокойная бумага | Свадьба |
| Классика | Вензель, торжественная рамка, тёплая отделка | Юбилей |
| Современный | Широкий гротеск, асимметрия, графический акцент | День рождения |
| Чистый | Деловая сетка, дата и место сразу, функциональная программа | Корпоратив |
| Ноктюрн | Тёмный портал, геометрия ар-деко и крупная дата | Вечернее событие |

Каждый шаблон допускает ровно три палитры и две согласованные пары шрифтов.
Оригинальные SVG/CSS-наборы и их style bible описаны в
`registry/studioTemplates.ts`. Это существующие нативные материалы; библиотека
не выдаёт их за коллекцию отобранных bitmap-иллюстраций.

## Создание и настройка

`Content.studioDesign` хранит выбранный шаблон и палитру отдельно от брифа.
Выбор не стирает текст пользователя. В режиме авто Claude видит совместимые
шаблоны, разрешённые IDs, бриф и референсы и возвращает:

```json
{
  "facts": null,
  "selection": {
    "templateId": "editorial",
    "paletteId": "ivory",
    "fontPairId": "editorial",
    "ornamentSetId": "editorial-rules"
  },
  "rationale": "Тёплая редакционная композиция подходит камерной свадьбе.",
  "photos": []
}
```

Свободные HEX, CSS, маски, рамки, промпты картинок и неизвестные IDs отсутствуют
в этом контракте. Код повторно проверяет совместимость и закреплённый выбор
владельца. История помогает автоматическому подбору, но допускает повтор
подходящего авторского шаблона.

Шаблон, выбранный без описания, собирается детерминированно без вызова модели.
Вариант получает `studioTemplate` с ревизией 1 и сохраняет его в теме, серии и
версиях. Старые приглашения продолжают читаться своими рендерерами.

В редакторе три палитры текущей версии меняются детерминированно и создают новую
неизменяемую версию. Текстовая доработка нового шаблона ограничена его палитрами,
шрифтовыми парами и включением собственного движения. Запрос другой композиции
требует выбора нового шаблона. Тексты, фотографии, даты, адреса и RSVP остаются
данными и редактируются существующим редактором.

При автоматическом подборе учитывается тип события; владелец может явно выбрать
другую художественную семью. Заголовки обращения, программы и отсчёта имеют
отдельные варианты для свадьбы, юбилея, дня рождения и корпоратива на ru/uz/en.
Prata и Tenor Sans используют проверенный локальный Cormorant для отсутствующих
узбекских глифов. Новые приглашения не запрашивают картинки у платного провайдера.

## Проверка

`scripts/qa-studio-templates.mjs` проверяет 320/390/430 px, полную вертикальную
страницу, 18 палитр, отсутствие переполнения, локальные шрифты, выбор без брифа,
сохранение через настоящий API, версии палитры, календарь, персонализированный
RSVP и его исходный POST, отсутствие JavaScript, reduced motion и desktop.
RSVP принимает локальный тестовый обработчик, временный проект удаляется.

Для API-части нужен изолированный сервер с пустыми `ANTHROPIC_API_KEY` и
`OPENAI_API_KEY`, чтобы сценарий не выполнял платных вызовов. При такой проверке
штатный AI-критик честно остаётся incomplete. Это не заменяется фиктивным pass.
Отдельно сохраняется браузерный отчёт и снимки каталога.

```sh
ANTHROPIC_API_KEY='' OPENAI_API_KEY='' \
QA_BASE_URL=http://127.0.0.1:3153 INVITATION_BUILD_DIR=.next-studio-templates \
npm run dev -- --hostname 127.0.0.1 --port 3153

STUDIO_PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs \
STUDIO_CHROME='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' \
STUDIO_QA_URL=http://127.0.0.1:3153 node scripts/qa-studio-templates.mjs
```

Unit/integration тесты проверяют транспорт модели с контролируемым провайдером,
неизменность авторских токенов, совместимость, реальные шрифтовые глифы,
сохранение фактов, фотографий, выбранных IDs, историю версий и старые режимы.

Дальнейший рост библиотеки — отбор самостоятельных иллюстрационных паков по этим
style bible. Перед подключением каждого пакета нужны визуальный отбор,
обработка и подтверждённые референсы семейства. Платёжные интеграции и хранение
ответов гостей не менялись в рамках обновления дизайна.
