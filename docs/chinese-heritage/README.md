# Chinese Heritage

В приложение добавлена редактируемая композиция по HTML владельца
`Свадебное_приглашение_RU.html`. Из исходника перенесены декоративные материалы
и характер дизайна: светлая бумага, красный конверт, золотые рамки, цветущая
слива, фонарь, акварельный сад и рукописные имена.

## Как открыть

Локальный запуск: `npm run dev`, затем `http://localhost:3000/`.
В коллекции выберите **Chinese Heritage**. Предпросмотр показывает вымышленные
данные; создание приглашения начинает пустой черновик.

Отдельная демонстрация открытия конверта:
`http://localhost:3000/dashboard/preview?template=heritage&locale=ru&entrance=1`.
Для узбекского языка замените `locale=ru` на `locale=uz-latn`.

В исторической студии `/studio` доступен тот же шаблон с ID `heritage`.
Явный выбор шаблона без брифа работает без обращения к AI. При генерации по
брифу модель выбирает ID из каталога; композицию строит renderer приложения.

## Что стало данными приложения

- Имена, тексты, дата, время, место, программа, дресс-код и фотографии
  редактируются через существующую модель приглашения.
- Пустые и отключённые разделы не заполняются фактами из образца.
- Серверная публикация использует сохранённый снимок. Последующие правки
  черновика появляются у гостей после обновления публикации.
- RSVP подключён к существующему серверному обработчику и кабинету владельца.
  Исходная форма с локальным `localStorage` не переносилась.
- Студийный адаптер сохраняет точный момент события, назначение фотографий,
  защищённое кадрирование и редактируемые поля.
- Шаблоны, палитры и версии, созданные раньше, остаются читаемыми.

Это добавление авторского шаблона. Импорт произвольного HTML с JavaScript и
генерация произвольных HTML/CSS не реализованы.

## Устройство

`components/platform/HeritageInvitation.tsx` строит страницу из данных;
`heritage-invitation.css` задаёт композицию. `HeritageEntrance.tsx` управляет
нативным диалогом конверта: клапан открывается, карточка выходит, затем
открывается страница. Встроенный предпросмотр сразу показывает страницу.
Серверный HTML остаётся читаемым без JavaScript. Системное уменьшение движения
учтено отдельной веткой открытия и CSS.

`components/layouts/HeritageStudioInvitation.tsx` связывает историческую модель
студии с тем же renderer. В customer-конструкторе добавлены `heritage`, палитра
`cinnabar` и пара шрифтов `romantic`; в студии используются совместимые токены
каталога. Шрифты загружаются из существующих локальных ресурсов проекта.

Длинные имена получают меньший кегль, сохраняя переносы и живой текст.
Узбекские названия месяцев и дней недели задаются явно: результат не зависит
от полноты узбекских локалей ICU в браузере. Часовой пояс события сохраняется.

Восемь уникальных декоративных WebP извлечены из предоставленного образца без
перекодирования (310 370 байт). Новая генерация изображений не выполнялась.
Происхождение и хеши: [manifest.json](../../public/artwork/chinese-heritage/manifest.json).
Подробное исследование исходника: [reference-study.md](reference-study.md).

## Проверка и границы

В браузере проверены коллекция из четырёх дизайнов, её предпросмотр, открытие
конверта и мобильные страницы на 320, 390 и 430 px. Проверены длинные имена,
русские и узбекские подписи, календарь, программа, место и прощание.
Горизонтальная прокрутка в проверенных сценариях отсутствовала.

Автоматическая проверка: `npm test`, `npm run typecheck`, `npm run lint`,
изолированная production-сборка и реальный HTTP smoke suite:

Финальный результат: **58 тестовых файлов, 521 тест — успешно**; TypeScript,
ESLint, production-сборка и HTTP suite прошли. Скриншоты:
[конверт](cover.jpg), [длинные имена на 320 px](long-names-320.jpg),
[узбекская дата на 430 px](uzbek-date-430.jpg).

```bash
PLATFORM_QA_BASE_URL=http://127.0.0.1:3100 \
PLATFORM_QA_PRODUCTION=1 PLATFORM_QA_TEMPLATE=heritage \
node scripts/platform-http-smoke.mjs
```

Для suite используется отдельный локальный сервер с временным
`PLATFORM_DATA_DIR`; он создаёт вымышленные аккаунты и приглашения.
Проверяются права владельца, ревизии, публикация, сохранённые снимки, RSVP
через JSON и обычную форму, архивирование, CSRF и доступ к медиа.

Платные AI-запросы, физические мобильные устройства и производительность на
медленной сети в этой проверке не запускались. Проверка без JavaScript и с
уменьшенным движением на этом этапе ограничена кодом и автоматическими
проверками серверной разметки; отдельного браузерного прогона этих режимов нет.
Размещение остаётся локальным; PostgreSQL, объектное хранилище и коммерческий
деплой требуют отдельного этапа.
