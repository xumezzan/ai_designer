# Рост приглашения внутри одного дизайна

У разделов закреплены семантические места: обложка с выбранным фото и именами → описание события → дата/отсчёт → локация → программа → дресс-код → пожелания → ответ гостя → прощание. Только заполненные разделы и размещённые фотографии видны гостю. Неизвестные данные не дописываются для увеличения длины страницы.

`invitationSectionOrder` объединяет сохранённый дизайн, новые данные и фото, затем располагает их в этом порядке. Добавленная после генерации локация появляется перед программой/дресс-кодом; позднее описание появляется под обложкой; прощание остаётся в конце. Старые JSON читаются с той же логикой без переписывания истории. Генерация и правки получают этот порядок как правило дизайн-кода.

Дизайн остаётся один. Цвет/фактура раздела закреплены за его ролью, а не номером дочернего элемента. Для cinematic локация вынесена из обложки в собственный раздел: название, фото, адрес, пояснение, ссылка на маршрут, календарь. Пустой адрес/блок подробностей не рисуется. Фото вступления предшествуют описанию, финальные фото предшествуют прощанию. Выбранный в редакторе раздел фото (`placementPinned`) имеет приоритет над сохранённым расположением генерации; качество и защищённый кроп сохраняются.

Пожелания добавлены как отдельный `content.wishes`/`wishes` раздел. Они редактируются на холсте и в «Слова и программа», скрываются после очистки. Описание, адрес, заметка о дороге, карта, пожелания и явно заданная программа могут заполняться из брифа в том же запросе генерации. Уже заполненные данные защищены; длинный известный текст не нужно повторно возвращать из модели. Дизайнерские инструкции не служат текстом пожеланий. Новая строка программы начинается с пустого времени, которое задаёт владелец.

Проверка: 335 тестов, production-сборка, мобильные ширины 320/390/430. `lib/invitation/sections.test.tsx` проверяет порядок после расширения короткой темы, очистку разделов, перенос заданного фото и положение прощания; `lib/studio/briefFacts.test.tsx` проверяет добавление содержимого из брифа и защиту ручных правок. `scripts/qa-live-editor.mjs` проверяет добавление/удаление пожеланий, позднюю программу, порядок в живом iframe, сохранение и повторное открытие. Browser QA использует один локальный дизайн без платных API.
